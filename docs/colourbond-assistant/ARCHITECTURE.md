# COLOUR BOND assistant architecture

This describes the checked-in PrestaShop COLOUR BOND widget and backend. The three widget directories currently contain copies; paths below use `prestashop-widget/` for the browser/proxy edge.

## Request and response flow

1. **User message and browser session** — `prestashop-widget/colourbond-chatbot.js`, `sendMessage()`, reads the input, creates/reuses `sessionId`, sends `conversation_id`, `session_id`, message, language, assistant name, and page URL to the local proxy. Contact-like messages are intercepted by `isContactRequest()` and handled locally by `showContact()`.
2. **Language/site resolution** — browser language is selected by `detectLanguage()` in `prestashop-widget/colourbond-chatbot.js` from `<html lang>` or the `lang-en` body class (`en`, otherwise `cs`). `prestashop-widget/colourbond-chatbot-proxy.php` validates the language and sends the server-held site token. Backend `siteAuth()` in `backend/src/lib/site-auth.ts` resolves that token to `SiteContext`. `ChatService.sendMessage()` in `backend/src/services/chat-service.ts` uses the requested language, then site language, then `sk`. `AIProviderRegistry.forSite()`/`readProfile()` in `backend/src/services/ai-provider-registry.ts` reads `siteContext.settings.sync_config.ai_config.assistant_profile`; `backend/src/index.ts` maps `colourbond_products` to `ColourbondProductProvider` and `nastroje_website` to `NastrojeAiProvider`.
3. **Conversation history** — `ChatService.resolveConversation()` creates/reuses the site-scoped conversation. `ChatService.sendMessage()` stores the user message, then `ConversationRepository.listRecentMessages()` in `backend/src/repositories/conversation-repository.ts` reads the latest eight messages in chronological order and maps them to `GenerateReplyInput.conversationHistory`. The current `ColourbondProductProvider.generateReply()` does not consume this field.
4. **Retrieval** — `ChatService.sendMessage()` calls `RetrievalService.searchRelevantContent()` in `backend/src/services/retrieval-service.ts` with the site ID, current message, limit 5, and profile. `DocumentRepository.searchChunks()` in `backend/src/repositories/document-repository.ts` dispatches `colourbond_products` to `searchProductKeywords()`. That function loads published product documents for the authenticated site, ranks them with `parseQuery()` and `scoreProduct()`, fetches their chunks, and returns one representative chunk per ranked product. Catalogue documents come from `SyncService.ingestBatch()` or developer importer functions `main()`, `loadActiveProducts()`, and `toDocument()` in `backend/scripts/import-colourbond-products.ts`; its checked-in source is `backend/data/colourbond-products.json`.
5. **Product grounding** — `ColourbondProductProvider.generateReply()` calls its `collectProducts()` to convert unique titled retrieval chunks into `GroundedProduct` objects. It then calls `partitionProducts()` in `backend/src/services/product-grounding.ts`. `constraintsForQuestion()` derives explicit outdoor and material requirements from the current message, and `partitionProducts()` splits products by whether their normalized catalogue text explicitly matches every derived constraint.
6. **Eligible/rejected products** — `generateReply()` keeps up to three eligible products in retrieval order. With no eligible product it calls `constraintReply()`; with eligible products it sends up to three eligible entries and all rejected entries through `buildContext()`. Rejected products are context only and must not become recommendations/cards.
7. **Provider/LLM or deterministic fallback** — `ColourbondProductProvider.generateReply()` first handles contact, complaint/return, order, greeting/capability, and no-context branches deterministically. For product answers, a missing `GROQ_API_KEY` calls `buildDeterministicReply()` with suffix `groq-unavailable`. Otherwise it calls Groq with `systemPrompt()`, `buildContext()`, and the current user message. A non-OK response uses `groq-fallback`; empty or guard-rejected output uses `groq-guarded-fallback`. The guards are `mentionsOnlyRetrievedProducts()` and `followsProductOrder()`.
8. **Text, sources, and cards** — accepted model text is parsed by `selectMentionedProducts()` in `backend/src/services/product-grounding.ts`, so the returned `products` array contains only eligible products whose exact normalized titles occur in the answer, in eligible order, capped at three. `ColourbondProductProvider.collectSources()` creates sources from those cards. Deterministic product replies return the selected eligible products and their sources directly. `ChatService.sendMessage()` persists text, sources, provider, products, and links, then returns them from `/api/chat/message` (`createChatRoutes()` in `backend/src/routes/chat.ts`).
9. **Proxy enrichment and rendering** — `colourbond_chatbot_enrich_products()` in `prestashop-widget/colourbond-chatbot-proxy.php` resolves localized PrestaShop names, descriptions, canonical URLs, and images for the backend cards and aligns matching source URLs. In `prestashop-widget/colourbond-chatbot.js`, `addMessage()` renders text, `addProductCards()` renders returned cards in array order, and `addResponseLinks()` renders action links. The widget currently slices cards to four; the provider currently returns at most three.

## Lead/brief flow

The generic WordPress brief UI is `wp-ai-assistant/public/src/widget.tsx`: it collects configured questions and posts them to the configured lead submit URL. Backend `createLeadRoutes()` in `backend/src/routes/leads.ts` validates and rate-limits the request. `LeadService.submit()` in `backend/src/services/lead-service.ts` creates/reuses a brief conversation, stores the answer transcript, builds a summary in `buildSummary()`, persists the submission, and returns the configured form success message.
